                                                                        Agentic Build Lab

                                                                        How this lab works · 5 minutes to read

                                                                        In one day you build a ServiceNow app, the HR Case Router. An AI agent moves each new HR case to the group or HR service that should work it, with a work note saying why. A case it can't route, or whose move a check stops, stays put, with a note. Fulfillers can click Reroute. It's the customer's own use case. Claude Code writes the code. You make the decisions, and checks decide whether work may go on.

                                                                        The method is what you learn: the AI types, people and checks decide. Modules 1 to 8 each have one catch, a moment where the process stops a mistake. Those moments are the lesson.

                                                                        Rules for the whole lab

                                                                        1. Never paste this guide into Claude. Only the text in 🤖 boxes goes in. Why: if Claude sees the checks, it can write to pass them, and they stop being checks.
                                                                        2. Passwords stay out of Claude. Type them only into your own terminal or your browser. Claude never runs now-sdk auth, the command that asks for your instance's password. Why: everything typed into Claude goes to the model and stays in the conversation's history.
                                                                        3. You decide when your instance changes. You install the app yourself. The only install Claude runs is the grade's, to lab-pdi, and it asks you first. Why: an install changes a live system, so a person decides when, as in real work.
                                                                        4. Never use a production instance. Why: the agent you build moves HR cases and writes notes on them; on production, those are real people's cases.
                                                                        5. Trust what a command prints, not what Claude says about it. Why: Claude's summary is a likely answer and can be wrong; the output is evidence you can check, or run again.
                                                                        6. Follow what really happens. Don't re-run a prompt to get a nicer answer. Write down what happened, and carry on. Why: Claude can answer differently each time, and re-running until it looks right hides the mistakes the lab is built to catch.
                                                                        ℹ️ Where a password does go

                                                                        Your instance's password goes into its login page in the browser, and into now-sdk auth, which you run in your own terminal window (first in Module 0 step 7). On Mac: your Mac's password, if sudo asks for it, goes into your own terminal window too. The lab's settings block now-sdk auth for Claude, so it can't happen by mistake.
