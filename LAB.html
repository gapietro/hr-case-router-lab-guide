                                                        Agentic Build Lab

                                                        How this lab works · 5 minutes to read

                                                        In one day you build a ServiceNow app, the HR Case Router. An AI agent moves each new HR case to the group or HR service that should work it, with a work note saying why. A case it can't route, or whose move a check stops, stays put, with a note. Fulfillers can click Reroute. It's the customer's own use case. Claude Code writes the code. You make the decisions, and checks decide whether work may go on.

                                                        The method is what you learn: the AI types, people and checks decide. Modules 1 to 8 each have one catch, a moment where the process stops a mistake. Those moments are the lesson.

                                                        Rules for the whole lab

                                                        1. Never paste this guide into Claude. Only the text in 🤖 boxes goes in. If Claude sees the checks, they stop being checks.
                                                        2. Passwords go into your own terminal or browser, never into Claude.
                                                        3. Claude never runs now-sdk auth. You install the app yourself. The only install Claude runs is the grade's, to lab-pdi, and it asks you first.
                                                        4. Never use a production instance.
                                                        5. Trust what a command prints, not what Claude says about it.
                                                        6. Follow what really happens. Don't re-run a prompt to get a nicer answer. Write down what happened, and carry on.

                                                        When Claude asks permission, read the command, then:

                                                        • 1. Yes for git, gh, npm, node, now-sdk build, now-sdk explain (the SDK's docs, nothing live) and now-sdk query --auth lab-pdi (reads records on your instance, writes nothing), or their npx @servicenow/sdk … forms, and for files in ~/projects/hr-case-router, Module 1's ~/projects/hr-case-router-prd-review or the kit's copy, ~/projects/prove-it-kit.
                                                        • No for now-sdk auth; for now-sdk install, deploy, exec, run, move or cicd, and npm run deploy, except the grade's install to lab-pdi; for any alias but lab-pdi, anything that names your instance, and anything in this guide's folder.
                                                        • Not sure? No, then ask Claude what it was for.
                                                        • Never choose "Yes, and don't ask again". The asking is the check.
                                                        • Auto mode asks less and blocks instead, showing Denied by auto mode classifier. Blocked the step's own action? Reply yes, and the action, such as yes, push the branch. If not, reply no, stop.
                                                        • Asked once "Allow this read outside the working directories?", choose Yes, and keep allowing any reads outside the working directories: the lab's settings still keep Claude out of this guide, your notes and your keys.

                                                        Words you'll meet

                                                        • Repo: a folder whose history git keeps. Your app's repo is ~/projects/hr-case-router/app.
                                                        • Commit: one saved snapshot in that history.
                                                        • Branch: a separate line of commits. main changes only through pull requests.
                                                        • Pull request: a request on GitHub to merge a branch into main. It's reviewed first.
                                                        • Story: one small piece of work, filed as a GitHub issue.
                                                        • Gate: a milestone that stories hold up: MERGE, INSTALL, DEMO, HANDOFF.
                                                        • Design term: one numbered rule in your design record, such as C3. Every test names the term it proves.
                                                        • Catch: a real problem the process found and that got fixed, or that changed a decision. A check firing on something you planted to test it isn't a catch.
